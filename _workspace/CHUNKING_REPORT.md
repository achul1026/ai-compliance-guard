## 4. 청킹 알고리즘

### 4-1. 계층 우선 분할

```
조(條) ≤ MAX_TOKENS(500) → 그대로 1청크
        > MAX → 항(項) 단위 분할
                ≤ MAX → 1청크
                > MAX → 호(號) 단위 분할
                        ≤ SOFT_MAX(700) → 1청크
                        > SOFT_MAX → 길이 기반 강제 분할
```

### 4-2. 정형 응답 처리 (그룹 C)

국가법령정보 Open API는 `<조문단위>` → `<항>` → `<호>` 의 명시적 XML 트리를 반환하므로 정규식 불필요. 항 머리말과 호 본문을 합쳐 측정한 뒤 임계치 초과 시 호 단위로 분리.

### 4-3. PDF 텍스트 처리 (그룹 A)

| 분할 단계 | 정규식 / 로직 |
|---|---|
| 본칙·부칙·별표 분리 | `^부\s*칙` / `\[별\s*표\s*\d*\]` 마커 |
| 조 | `^제(\d+)조(?:의(\d+))?(?:\s*\(([^)]+)\))?` |
| 항 | 원문자 `^[①②③...]` 또는 `^\(\d+\)` 패턴 |
| 호 | `^\s*\d+\.\s` (들여쓰기 무관) |
| 부칙 충돌 방지 | 부칙 청크의 `article` 필드를 `부칙_제N조` 등으로 prefix |

### 4-4. 강제 분할

- 호 단위로 자른 후에도 SOFT_MAX(700) 초과 시 `force_split_by_length` 적용 (줄 단위로 잘라 MAX 안에 들어오도록 분배)
- 호 라벨이 없는 경우(별표·법령 본문 머리말 등)도 동일 처리

## 9. 관찰된 한계 및 후속 과제

### 9-1. 짧은 청크 비중 (현황)

법령 호 단위는 본질적으로 짧음. 단독 임베딩 시 시맨틱 유사도 매칭 정확도가 낮을 수 있음.

**후속 옵션** (임베딩 후 Recall@K 평가 결과에 따라 결정):
- **a. 부모 조항 컨텍스트 prepend**: 호 청크 텍스트 앞에 "제8조 제1항 / " 같은 머리말 추가 → 시맨틱 정확도 ↑
- **b. 인접 호 병합**: 같은 항의 호들을 묶어 항 단위로 재구성 → 정보량 ↑, 조항별 직접 매칭 ↓
- **c. 그대로 두기**: BM25 키워드 검색이 호 단위 정확 매칭에 강점 → 하이브리드 검색으로 보완

→ **권장**: 1차 임베딩 → Recall@K 측정 → 부족하면 (a) 적용 후 재평가.

### 9-2. OCR 사례집 (그룹 B) 미진행

`온라인_부당광고_사례집_식약처_2022_20260526.pdf` (84p, 이미지 기반):
- Tesseract Korean 설치 부담 (Windows에서 별도 설치 파일)
- 사례집은 **위반 유형 학습/예시용**이라 본문 규제(이미 확보) 대비 후순위
- Day 3 별도 트랙으로 처리, Phase 1 임베딩·검증과 병행 가능

### 9-3. 시행령·시행규칙 미수집

본 인벤토리는 모법(법률) 3종만 포함. 시행령·시행규칙은 식약처 고시·가이드라인이 일부 흡수하고 있지만, 정밀도 향상을 위해 향후 보강 고려.

### 9-4. PDF 페이지 헤더·푸터 잡음

일부 PDF 청크에 "- 7 -" 같은 페이지 번호가 본문에 섞임. 영향은 작지만, 임베딩 정확도 평가 후 정제 룰 추가 검토.
